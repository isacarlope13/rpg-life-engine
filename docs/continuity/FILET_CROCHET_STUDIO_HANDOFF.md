## Fase 6A/6B.2 — Finalización Filet atómica (2026-11-24)

- **Identidad.** `universal-session-engine.ts` transmite el `sessionId` existente en finales Filet. El comando se conserva antes de enviarlo. La RPC comprueba el proyecto y su versión para el dueño autenticado, deriva la clave canónica en PostgreSQL y mantiene alias por operación. El bloqueo y la clave primaria del recibo serializan la misma sesión. El hash vincula el proyecto, la versión y los datos de la sesión. Una clave reutilizada con datos incompatibles devuelve conflicto. Las actividades legacy con la clave universal ya usada se bloquean para reconciliación.
- **Ruta.** `filet-session-finalization.ts` construye el plan a partir del proyecto, perfil y tesorería del propietario. Los valores XP y GP del cliente quedan fuera del plan. `skill-session/route.ts` devuelve el recibo atómico sin ejecutar el camino genérico para Filet. Usa recurso `none`, mantiene el contador de vueltas guiadas y devuelve 503 recuperable si falta la RPC. La creación de un proyecto Filet guarda ahora versión y snapshot en la fila de PostgreSQL. Las sesiones tradicionales conservan la ruta previa.
- **HTTP integrado.** `tests/filet-session-native-http.mjs` usa Next.js y PostgreSQL 17.11 real en loopback, con un doble HTTP de Auth/PostgREST.
